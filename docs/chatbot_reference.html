Référence Chatbot — AI Support Agent (Ingénieurs N3)

Version destinée aux ingénieurs N3 en production : détails techniques, signaux de confiance, et comment extraire des réponses fiables depuis le chatbot.

1) Objectif de ce document

Document succinct et orienté opération : comprendre les capacités du chatbot en production, repérer les signaux de fiabilité (trust), et savoir extraire l'information technique utile sans exiger de commandes d'administration ou d'accès backend.

2) Intentions et routage

  • diagnostic_request — erreurs, codes, stack traces (RAG + conversation).
  • procedure_lookup — récupération d'une FR/Procédure (KB-first).
  • root_cause_exploration — consolidation des indices entre tickets/procédures.
  • log_investigation — orientation sur quelles traces analyser et où les trouver.
  • ticket_summary / ticket_closing — synthèse & message à coller dans la carte Jira.
  • find_jira / explain_jira — recherche par mots-clés ou par clé issue (pattern [A-Z]+-\d+).
  • explain_data_model — exposé structuré du schéma BRASIL (tables, PK, FK, colonnes).
  • knowledge_gap_detection — indique l'absence de procédure formelle (fallback).

3) Cas d'usage opérationnels (N3)

3.1 Explainer schéma (ex: t_ports)

Requête recommandée (expliquer) 
Explique la table t_ports : PK, colonnes importantes (types), FK sortantes et tables qui la référencent. Cite les sources (snippet_id / procedure_id).

Attendu : réponse structurée contenant :

  • Vue synthétique (rôle de la table dans BRASIL)
  • Clé primaire (ex: port_id)
  • Colonnes clés (statut, timestamps, identifiants de relation) avec types
  • Relations : FK sortantes (cible) et FK entrantes (tables qui réfèrent)
  • Sources exactes (snippet_id, FR, ou lien Jira) — indispensable pour vérification

3.2 Explication d'une carte Jira

Requête recommandée 
Explique JIRA BRASIL-10861 en 4 points : contexte | symptôme | actions exécutées | prochaines étapes (en termes techniques)

Lorsqu'une clé est fournie, le pipeline effectue un lookup direct et peut reformuler la description via l'LLM. Vérifiez systématiquement la section sources renvoyée par le chatbot.

4) Signaux de fiabilité à contrôler (N3)

  • Sources listées : presence de snippet_id, procedure_id, ou lien Jira. Sans source, la réponse est faible.
  • Trust score / label : valeurs élevées (ex: 80-100) indiquent provenance KB validée ; scores bas suggèrent hypothèse.
  • Context blocks : si l'orchestrator renvoie plusieurs context_blocks, vérifiez qu'elles correspondent aux FR citées.
  • Mémoire conversationnelle : si une procédure antérieure est identifiée (prior_procedure_id), le chatbot doit la réutiliser et ne pas inventer une autre solution.
  • Anti-hallucination rules : le LLM est instruit à ne PAS inventer colonnes, FK ou étapes non présentes dans les sources.

5) Extractions techniques — comment demander

  1. Demande toujours la liste des sources et copie les snippet_id ou procedure_id renvoyés.
  2. Pour les tables : demande explicitement PK / colonnes importantes / FK out / FK in.
  3. Pour les procédures : demande l'identifiant FR et les étapes numérotées; exige la citation de la FR.
  4. Pour les tickets Jira : exige la clé + demande une reformulation technique ciblée (N3) et les logs/commandes mentionnés.

6) Règles opératoires en production

  • Ne pas exécuter de commandes ou tests depuis le chatbot : reste en lecture et récupération de connaissances.
  • Valider toute action corrective par une procédure FR existante et par revue humaine avant exécution.
  • Si une information critique manque, créez une FR et notez le snippet_id / contexte précis pour injection ultérieure dans le KB.
  • Pour extraire des données échantillons ou exécuter des requêtes SQL, suivez la procédure interne d'OPs (hors chatbot).

7) Prompts techniques (exemples pour N3)

Table — explicitation

Explique la table t_ports en donnant : (1) rôle et contexte ; (2) PK ; (3) colonnes critiques avec types ; (4) FK sortantes et FK entrantes ; (5) sources (snippet_id / FR).

Jira — reformulation N3

Pour BRASIL-10861, rédige en 4 points pour N3 : Contexte technique | Symptôme observé | Actions déjà menées (préciser logs/commandes citées) | Prochaines étapes recommandées.

8) Limitations & recommandations

  • Le chatbot ne doit pas remplacer les procédures d'exploitation ; il sert d'aide à la décision et de synthèse documentaire.
  • Toujours joindre les sources renvoyées pour audit (snippet_id, procedure_id, lien Jira).
  • Pour requêtes en production (extraction de données), utiliser les pipelines OPs autorisés et la revue humaine.
